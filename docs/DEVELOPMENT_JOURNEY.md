# JARVIS-Hand development journey

This project grew through bounded experiments. We kept baseline controllers and upstream assets intact, and treated an attractive render as insufficient evidence of physical behavior.

| Phase | Challenge | Hypothesis | Experiment | Observed result | Lesson learned |
|---|---|---|---|---|---|
| 1 — choose a stable hand model | Integrate Unitree Dex5 through somehand without obscuring physics failures. | The preferred hand could provide a suitable first MuJoCo actuator-control baseline. | Tried the somehand core API and Dex5 model. Then tested the asset as-is and a bounded integration/gain variant. | The core API loaded 20 actuators, but the raw asset produced BADQACC, extreme velocity, and about 24.7 mm initial penetration. The tuned short run was numerically stable but retained penetration and only 19/20 joints crossed the motion threshold. Switched to Menagerie LEAP; all 16 actuators visibly moved and its 60-second stepping test passed. | Numerical stability and contact validity must both pass. We rejected Dex5 for this baseline instead of hiding penetration or editing upstream physics. |
| 2 — live mirror | Make a real hand, not a canned trajectory, drive a robot hand in real time. | 21 webcam landmarks can be mapped to the LEAP's four modeled digits with conservative geometry, limits, and tracking-loss handling. | Built MediaPipe capture, calibration, named-joint mapping, filtering, command-rate limits, neutral recovery, and split-screen MuJoCo rendering. Investigated a reported simulation reset at step 13,534. | Real webcam detections produced visible LEAP finger motion. An intentional viewer reset at the `viewer.sync()` boundary reproduced the exception pattern and was classified separately from physics failure; the original historical command/model was not independently recovered. Long physics runs passed, while numerical faults continued to raise. Earlier camera measurements were 7.49–10.31 unique FPS; robot/display about 28 FPS. | Separate viewer reset events from numerical instability. Software frame-to-render time is not full physical motion latency. |
| 3 — personalize LEAP retargeting | Improve the generic ROM mapping using this operator's movement examples. | A lightweight personal model can learn useful motion correspondence while running on CPU. | Ingested 34 videos, split by whole recording (24/5/5), extracted 3,672 valid detections from 3,905 sampled frames, generated LEAP targets by bounded geometry optimization, and trained a 79→128→128→16 MLP with 28,816 parameters. | Held-out fingertip/pinch geometry proxy: ROM 61.32/41.12 mm; MLP 32.96/16.68 mm; optimization teacher 27.83/8.93 mm. | The personal model improves over ROM on this target definition, but the optimizer is more accurate. Targets are geometry-derived, not observed robot labels; one operator's clips do not prove new-user generalization. |
| 4 — physical grasping | Determine whether physical contacts can sustain a lift. | Better thumb opposition, actuator tracking, and contact-aware closure might create stable opposing contacts. | Ran bounded LEAP and G1 object trials with contact and force telemetry, retaining the documented lift/contact/hold criterion. | Valid sustained LEAP holds remained 0/5. G1 single-hand and assisted attempts also remained 0/5; some scenarios were rejected for deep contact penetration. | Closing fingers or transiently lifting an object is not success. We retained failed results and did not weld, teleport, or relax success criteria. |
| 5 — transfer to a humanoid hand | Test whether LEAP-learned movement preserves geometry on a different hand. | Mapping through fingertip geometry may transfer better than copying LEAP angles to Shadow. | Integrated a fixed-pelvis Unitree G1 with two Shadow Hands. Compared direct Shadow ROM, ROM→LEAP FK→Shadow, and personal MLP→LEAP FK→Shadow on the same five held-out personal recordings. Arm targets and left-hand coordination were scripted. | Normalized Shadow fingertip error: direct ROM 0.918, ROM geometry transfer 0.895, personal MLP transfer 0.944. Neural cross-embodiment transfer did not beat simpler baselines. | Different anatomy, thumb axes, tendon coupling, and coordinate frames break naïve transfer. Robot motion alone is not cross-embodiment generalization. |
| 6 — optional adaptive precision | Balance neural inference speed with geometric alignment. | Selectively invoking an optimizer may improve target geometry when precision matters. | Added optional v6 neural/optimizer/hybrid selection with hysteresis, limits, fallback, and a shared accepted-subset evaluation. Kept v5 neural as the default. | On 866 accepted observations, raw fingertip error was neural 31.11 mm, hybrid 27.28 mm, optimizer 22.06 mm. Physical replay was 49.93 mm neural-filter reference and 50.10 mm hybrid. The attended user test reported no obvious live improvement. | Better geometric targets did not improve physical execution. v6 remains optional and its result is a measured tradeoff, not a physical accuracy win. |
| 7 — physics-aware correction | Test whether MuJoCo state feedback could close the physical tracking gap. | A bounded model-bias residual might compensate position-servo gravity/load error. | Instrumented actuator controls, actual `qpos/qvel`, force, contact, and fingertip FK; confirmed the existing LEAP actuators are already position servos. Tested capped residual correction and scheduling against the same five clips; ran one paired 5-trial grasp comparison. | v7 physical fingertip error was 50.081 mm versus 49.932 mm v5 on the matched test set; this is 0.299% worse, far from the aspirational 5% gain. Holds remained 0/5 versus 0/5. No numerical warnings appeared, but measured servo error was smaller than the gap between filtered command geometry and raw target geometry. | A second PID would duplicate existing servo feedback. The reference shaping/retargeting gap dominated this experiment; v7 was rejected and kept out of release. |

## Guided pinch investigation

A local guided pinch recorder was prepared and used for a session showing the operator's hand, MediaPipe landmarks, LEAP motion, gesture prompts, and diagnostics. It did not establish a controlled before/after accuracy improvement or a validated controller correction. It remains an unpublished diagnostic investigation; it is not a new release capability or a scientific claim of improved pinch transfer.

## Assumptions we kept visible

- Monocular image/world landmarks are proxies and do not provide calibrated external 3D hand ground truth.
- LEAP joint targets come from a geometry objective, not human-worn robot sensors.
- The dataset is from one operator; held-out recordings are not held-out users and may share a recording session/background.
- The G1 pelvis is fixed; its arms are controlled by scripted targets and left-hand coordination is scripted.
- Physical manipulation remains unsuccessful under the documented sustained-hold criteria.
- v6's shared accepted-subset metrics use 866 observations, while the original LEAP test results use 921; those evaluations are not interchangeable.

The project's resulting contribution is a personally trained CPU retargeter, a tested real-time LEAP mirror, a measured set of analytic/learned/optimization comparisons, and a reproducible negative result on cross-embodiment transfer and grasping—not an RL-finetuned VLA.
